Політика приватності

Коротко. Застосунок не створює облікових записів і не має окремої системи аналітики. Налаштування й історія зберігаються на пристрої. Мережеві дані передаються лише відповідно до ввімкненого режиму — серверу Світлобота або Telegram.

1. Дані, що зберігаються на пристрої

Залежно від режиму застосунок зберігає ваші налаштування, ключ каналу Світлобота, ідентифікатор Telegram-каналу, журнал подій і чергу повідомлень для повторної доставки. Токен Telegram-бота зберігається в iOS Keychain. Ключ каналу та інші налаштування зберігаються у сховищах застосунку.

Застосунок не надсилає ці дані власній системі облікових записів, реклами чи аналітики. Резервне копіювання пристрою та його системні журнали контролюються iOS і вашими налаштуваннями системи.

2. Режим Світлобота

Коли ви вмикаєте моніторинг, застосунок надсилає серверу Світлобота запити про стан моніторингу. Запит містить ключ каналу та технічний сигнал про заряджання пристрою. Ключ передається як параметр URL-запиту. Сервер Світлобота отримує також мережеві метадані, потрібні для обробки запиту, наприклад IP-адресу. Застосунок може надсилати додатковий сигнал після припинення заряджання, якщо ви ввімкнули цю функцію.

Сервер Світлобота визначає статус каналу та, відповідно до своєї роботи, може створити повідомлення в Telegram. Його правила зберігання й використання даних регулюються політикою сервісу.

3. Telegram-fallback

Якщо ви ввімкнули fallback, застосунок звертається безпосередньо до Telegram Bot API для перевірки бота й каналу та для надсилання повідомлень. Telegram отримує токен бота, адресу каналу й текст повідомлення про зміну заряджання. Текст може містити час події та тривалість попереднього стану. Токен передається до офіційного Telegram API через HTTPS у шляху запиту.

Telegram зберігає й обробляє інформацію відповідно до власних правил. Учасники каналу можуть бачити надіслані туди повідомлення. Не використовуйте бот із токеном, який ви не маєте права застосовувати, і захищайте токен як пароль.

Якщо надсилання не вдається через мережу, текст повідомлення може залишатися в локальній черзі до повторної спроби. Повідомлення не надсилаються в режимі fallback через сервер Світлобота.

4. Зберігання й контроль даних

Локальні налаштування, журнал і черга залишаються на пристрої, доки їх не буде змінено чи видалено користувачем або операційною системою. Застосунок не встановлює власний період зберігання даних на серверах, оскільки не має серверного облікового запису чи власного сервера аналітики. Видалення мережевих даних із систем Світлобота або Telegram визначається відповідним постачальником.

Щоб припинити мережеві запити режиму Світлобота, вимкніть автоматичний моніторинг. Щоб зупинити Telegram-повідомлення, вимкніть fallback і відкличте токен у BotFather, якщо він вам більше не потрібен. Відкличте токен негайно, якщо вважаєте його розкритим.

5. Сторонні сервіси та вебсайт

Режим Світлобота залежить від серверу Світлобота, а fallback — від Telegram. Ця політика описує роботу iOS-застосунку, але не замінює правила цих сервісів.

Сайт документації розміщується GitHub Pages. Під час перегляду GitHub може обробляти технічні дані запиту за власною політикою приватності. Сайт не завантажує сторонні шрифти, рекламні трекери чи власний JavaScript-аналітики.

Apple й інші системні служби можуть обробляти діагностичні дані відповідно до ваших налаштувань пристрою та їхніх правил.

6. Діти

Застосунок є утилітою для моніторингу пристрою й не призначений для збору відомостей про дітей.

7. Зміни політики

Оновлена версія публікуватиметься на цій сторінці з новою датою набрання чинності. Значні зміни також можуть бути описані в примітках до відповідного оновлення застосунку.

Privacy Policy

Effective date: 6 October 2026

In short. The app has no user accounts or separate analytics system. Settings and history are stored on the device. Network data is sent according to the selected mode: to the SvitloBot service or to Telegram.

Data stored on your device

Depending on the enabled mode, the app stores your settings, SvitloBot channel key, Telegram destination, event history, and pending messages for retry. The Telegram bot token is stored in the iOS Keychain. The channel key and other preferences are stored in app storage. The app does not send this information to its own account, advertising, or analytics service. Device backups and system diagnostics are controlled by iOS and your device settings.

SvitloBot mode

When monitoring is enabled, the app sends monitoring requests to the SvitloBot server. A request contains the channel key and a technical signal about charging status. The key is sent as a URL query parameter. The server also receives network metadata needed to process the request, such as the device's IP address. If enabled, the app may send one additional signal when charging stops. The SvitloBot server determines channel status and may publish a Telegram message under its own service rules. Server-side retention and use are governed by the service operator.

Telegram-fallback mode

When fallback is enabled, the app contacts the Telegram Bot API to verify the bot and channel and to send messages. Telegram receives the bot token, channel destination, and message text describing a charging transition. A message may include the event time and the duration of the previous state. The token is sent over HTTPS in the request path to Telegram's official API. Telegram processes data under its own policies, and channel members can see messages posted there. Failed network sends may remain in a local queue until retried.

Retention and control

Local settings, history, and queued messages remain on the device until changed or removed by the user or operating system. The app does not set a server retention period because it has no account backend or app-operated analytics server. Deletion of data held by SvitloBot or Telegram is governed by each provider. Disable automatic monitoring to stop SvitloBot requests. Disable fallback and revoke the bot token through BotFather when you no longer need it or believe it has been exposed.

Third-party services and this website

SvitloBot mode depends on the SvitloBot service; fallback depends on Telegram. This policy covers the iOS app and does not replace those services' policies. This documentation site is hosted by GitHub Pages. GitHub may process technical request data under its privacy statement. The site does not load third-party fonts, advertising trackers, or app-operated JavaScript analytics. Apple and other system services may process diagnostics according to device settings and their policies.

Children, changes, and contact

The app is a device-monitoring utility and is not designed to collect information about children. Updates to this policy will be published here with a revised effective date. Questions may be sent to svitlobot@gmail.com. Report vulnerabilities privately using the security page.
